# 打票探测保护与日志

本次按 `sub2api-for-mg-v0.2.7.zip` 中的功能实现，保留本项目既有门票生命周期、降级撤票版本屏障和本轮计数，不直接替换整套源码。

## 401 探测与停票

在现有打票请求收到上游 HTTP 401 时识别令牌失效，不增加独立的高频探测任务，也不在业务请求里现场打票。

- 记录账号 token 和实际发送 token 的哈希，停止该账号所有模型的后续打票；已发出的请求不追溯取消。
- 使用条件 SQL 标记账号错误、不可调度，同时写调度 outbox。账号已更换 token 或已手动停用时，旧请求的 401 不得覆盖新状态。
- 失效标记写入现有 server-managed `extra` 命名空间，账号编辑保留、导出排除；不记录 token 原文。
- 凭据实际更新后旧哈希不再匹配。仅清除错误但仍使用同一个失效 token，不会重新打票。
- 写库失败时当前进程仍保留内存停票状态；不保证数据库故障后重启还能保留未写入的状态。

## 没额度不打票

按参考版本的确认口径：打票请求返回 429，且响应额度窗口或可信的已有额度快照显示 5 小时/7 天窗口耗尽时，记录打票暂停标记。单独 429、网络错误、缺少额度信息都不等于没额度。

- 后续扫描与实际发送前都会检查暂停状态；现有账号限流期间也不打票。
- 窗口重置或更新、更可信的额度快照显示恢复后，允许现有周期继续打票。
- 旧快照不能撤销刚观察到的暂停；缺少重置时间的暂停最多保留对应 5 小时或 7 天。
- 仅暂停打票，不因合成探测给业务另加账号冷却、改变业务用量快照或修改已有票。
- 不改变打票代理、周期、超时和 292 有效票成功条件。

## 日志统计

账号列表或编辑弹窗中，点击“打票 N 次”打开日志。只在弹窗打开时每 5 秒刷新，关闭后取消请求与定时器。

- 每个账号/模型最多 200 条内存事件；最多保留 512 个账号/模型流，LRU 淘汰，重启清空。
- 展示本轮序号、时间、开始/响应/保存结果、HTTP 状态、票长和耗时。
- 保存失败或撤票版本过时不能记成保存成功；收到合法票与成功保存是不同事件。
- 汇总仅统计当前保留事件里的请求数、保存数和未成功数，不是历史总量或成功率。
- 使用现有管理员鉴权下的 `GET /api/v1/admin/accounts/:id/codex-ticket-logs?model=...`；查询只读，不触发打票、不增加计数，不写数据库。
- 不返回票原文、API key、token、代理凭据、请求正文或原始上游错误。没有移植出口 IP、国家查询等额外诊断。

之前的本轮计数规则保持不变：实际请求前 +1；未发送不计数；成功保留；提前刷新累计；过期或降级撤票归零；重启归零。401/额度暂停本身不额外清零。
